# Contexto Global del Proyecto: CreatorFloww (OnlyFans Agency CRM)
- Stack: Tauri v2 (Rust backend) + React (TypeScript) + Tailwind CSS + Lucide React + Recharts + SQLite (`rusqlite`).
- Diseño UI/UX: Estilo Infloww CRM (minimalista, limpio, tarjetas blancas con bordes `border-slate-200`, sombras suaves `shadow-sm`, tipografía nítida, acentos en azul/naranja corporativo).

# REGLAS ESTRICTAS E INQUEBRANTABLES:
1. PROHIBIDO INVENTAR DATOS FALSOS (NO MOCK DATA): Nunca uses `Math.random()`, arreglos estáticos de prueba (`mockData`, `dummyData`, `fakeUsers`), ni simulaciones con `setTimeout`.
2. ESTADOS VACÍOS REALES: Si la base de datos SQLite está vacía o no hay cuentas sincronizadas, la interfaz DEBE mostrar `$0.00`, `0%`, `"No data"`, `"No employees have clocked in"`, `"Insufficient data"` o `"Unknown"`.
3. PREVENCIÓN DE MÉTRICAS INFLADAS/DUPLICADAS: Toda transacción, mensaje o fan extraído de OnlyFans debe guardarse en SQLite usando su ID real único de OnlyFans con cláusulas `UNIQUE` y `INSERT INTO ... ON CONFLICT DO UPDATE` para no duplicar ni inflar jamás las ganancias al sincronizar varias veces.
4. SIN PROXIES: No implementes lógica de proxies. Las conexiones usan la red directa en particiones WebView aisladas.
5. TRABAJO MODULAR PASO A PASO: Solo escribe el código de la fase que el usuario te pida en el prompt actual. No adelantes código de fases futuras ni dejes comentarios tipo `// TODO: implement later` dentro de la fase actual. Todo código entregado en un paso debe ser 100% funcional y compilable.
